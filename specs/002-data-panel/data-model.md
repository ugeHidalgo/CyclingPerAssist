# Data Model: Data Panel Experience

## Persisted API entity

### `PanelSetup`

One row stores the confirmed setup for one owner. The v1 owner key is the server-controlled
value `default`; the API does not accept an owner key from the browser.

| Field | Type | Constraints and meaning |
| --- | --- | --- |
| `id` | UUID | Primary key, generated by the API on the first confirmed save and retained on later saves. |
| `owner_id` | Text | Required; `default` in v1. Unique index enforces one setup per owner. |
| `title` | Varchar(200) | Required; empty string is allowed. |
| `x_px` | Integer | Required, non-negative; horizontal position relative to the Data Area. |
| `y_px` | Integer | Required, non-negative; vertical position relative to the Data Area. |
| `width_px` | Integer | Required, minimum 200. |
| `height_px` | Integer | Required, minimum 200. |
| `source_handle_id` | UUID, nullable | Opaque client-generated key for a browser file handle. Null if persistent handle support is unavailable or no handle could be retained. |
| `source_file_name` | Text, nullable | Selected filename for display and unavailable-source messaging. Null only when no source has been selected. |

### Invariants

- The database enforces primary-key uniqueness, one row per owner, non-negative position,
  minimum panel dimensions, and a title length no greater than 200 characters.
- `source_file_name` may be present while `source_handle_id` is null. The current session can
  still use the selected `File`, but the source cannot be guaranteed to reopen after restart.
- If `source_handle_id` is present, `source_file_name` must also be present.
- The database never stores activity bytes, parsed telemetry, chart points, browser handle
  objects, or absolute filesystem paths.
- Save is an owner-key upsert. The last successfully committed write is the saved setup; the API
  returns the persisted representation after commit.
- The API does not create a setup merely because the application opens. First use remains an
  in-memory default until the user confirms Save.

## Browser-local handle record

IndexedDB stores a structured-cloned `FileSystemFileHandle`, keyed by `source_handle_id`.
This is browser-origin/profile data, separate from the server's PostgreSQL volume. Store no file
contents in IndexedDB. A cleared browser profile, revoked permission, unavailable file, or
container move to another machine can make the handle unavailable while leaving the saved panel
metadata intact.

On startup, the client retrieves the handle and checks read permission. It reads the file only
when permission is already granted. A permission state that requires user activation is treated
as unavailable at startup; the panel shows its saved filename and warning rather than prompting
automatically. On browsers without the File System Access API, a regular file input supports
the current session but not guaranteed source restoration.

## Client-only panel state

The client keeps the current panel values, last confirmed setup snapshot, chart/activity state,
and source availability in memory. Dirty state compares persisted fields only (title, geometry,
filename, and optional handle ID); loading state and chart telemetry are not persisted.

The unavailable-source presentation is a runtime state, not a database update: keep the
confirmed setup unchanged, show its filename and warning, and render the title and chart blank as
required. A failed replacement retains the last successfully loaded activity and source.

## Save and restore lifecycle

1. **No setup**: `GET /api/v1/panel-setup` returns 404. Render the default panel; do not write a row.
2. **Select source**: read and parse the selected `File` in the browser. If a persistent browser
   handle is available, store that handle in IndexedDB and associate it with an opaque UUID.
3. **Edit**: keep geometry, title, source reference, and unsaved state in the client. A declined
   Save changes no server state and exits title-edit mode.
4. **Confirm Save**: after the user's confirmation, `PUT` the setup metadata. A failed request
   or local handle-storage failure is reported; retain current state as unsaved and leave the
   previous server setup unchanged.
5. **Restore**: read the saved setup from the API, then look up its optional handle ID in
   IndexedDB. If the file and permission are available, load it through the existing FIT
   adapter. Otherwise, show the saved filename and unavailable warning with a blank chart.

## Existing domain model

The panel does not add a new activity or telemetry entity. It reuses the current format-independent
`SelectedActivity` model and the existing FIT adapter/chart boundary. Activity data remains
session-memory-only and is never part of `PanelSetup`.
